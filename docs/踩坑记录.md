# 踩坑记录

这份清单是本方案能跑起来的真正原因。按"现象 → 原因 → 处理"整理，供复现和排错参考。

---

## 一、运行时（壳跑不起来）

### 1. `import { app } from 'electron'` 直接抛错

**现象**：`SyntaxError: The requested module 'electron' does not provide an export named 'app'`

**原因**：Electron 的包是 CommonJS，产物经 tsc 编译成 ESM 后，命名导入在 ESM 链接阶段就失败。

**处理**：`postbuild.mjs` 把命名导入改写成
`createRequire(import.meta.url)('electron')` 再解构。

### 2. 打包态用 Electron 自身当 Runtime 会被拒绝

**现象**：`node-addon-require-builtin unsupported: unsupported Electron runtime fingerprint`

**原因**：官方源码在打包态取 `process.execPath` 作为"内置 Node"。未做安装器替换时它是 Electron，
而 Electron 内置 Node 的 V8 指纹不在 addon 的允许列表里。

**处理**：`postbuild.mjs` 把 `: process.execPath;` 换成基于 `app.getAppPath()` 的
`runtime/node/node.exe`，即真正随包分发的 Node。

### 3. `process.resourcesPath` 的层级不可靠

**现象**：内置 Node 明明在 `resources/app/runtime/node/node.exe`，拼接结果却少了 `app` 一层。

**处理**：运行时与 pnpm 一律用 `app.getAppPath()` 定位（与 dsh 自身的解析方式一致）。

### 4. 主窗口永远不出现

**现象**：进程活着，窗口句柄存在但 `IsWindowVisible=false`，看不到任何界面。

**原因**：官方以 `show: false` 起步，等后端就绪才 `show()`。后端一旦卡住，用户只会面对"什么都没有"。

**处理**：`postbuild.mjs` 把 `show = false` 改成 `show = true`，至少能看到启动页与恢复按钮。

### 5. 开发态必须开 Host 调试端口

**现象**：`profile bundle "@deepseek-ai/dsh-base" resolved outside the Desktop runtime and profile`

**原因**：壳只有在 `DSH_DESKTOP_HOST_INSPECT_PORT` 存在时，才会给 Host 子进程传
`--allow-linked-profile`（官方给开发态留的逃生门）。

**处理**：`dev-start.mjs` 里固定设置该环境变量。

### 6. 单实例锁会吃掉第二次启动

**现象**：打包版启动后立刻以 code 0 退出，无任何报错。

**原因**：已有实例（例如开发态那个）持有单实例锁。

**处理**：测试前先结束已有实例。诊断时用 `process.pid` 与进程数交叉确认。

## 二、依赖与打包

### 7. `extraResources` 会丢掉 node_modules

**现象**：配置里写了 `extraResources` 指向运行时目录，结果只复制进 1 个文件（23293 → 1）。

**处理**：改用 `afterPack` 钩子直接 `fs.cp` 进 `resources/app`。

### 8. workspace 依赖不会被收集

**现象**：`ERR_MODULE_NOT_FOUND: Cannot find package '@deepseek-ai/dsh-home-paths'`

**原因**：它在官方 `package.json` 里声明为 `workspace:^`，electron-builder 不收集；
但壳的 `paths.ts` 启动时就会 import 它。

**处理**：`afterpack.mjs` 从运行时树里把它补进 `resources/app/node_modules`。

### 9. 运行时依赖在嵌套位置

**现象**：`Cannot find package 'chokidar' imported from .../dsh-app-boot/lib/index.js`

**原因**：本机安装把依赖放在 `@deepseek-ai/dsh/node_modules/`（嵌套），
而 Host 从运行时顶层解析，找不到。

**处理**：`materialize-runtime.mjs` 把嵌套依赖**扁平化提升**到运行时树顶层。

### 10. `@electron/get` 的动态导入拿到 undefined

**现象**：`TypeError: Cannot read properties of undefined (reading 'ReadWrite')`（electron-builder 内部）

**原因**：`@electron/get` 是 CJS，app-builder-lib 用 ESM `import()` 后访问命名导出，
只有 `default` 有值；它需要的 `ElectronDownloadCacheMode` 枚举在 v3 里根本不存在。

**处理**：本方案不用 electron-builder 的下载链路（`electronDist` 指向本地分发），
并在必要时给 `@electron/get` 补枚举 shim。

### 11. NSIS 工具链下不动

**现象**：`Response code 404` / 超时，卡在 `nsis-bundle-3.12.tar.gz` 或 `nsis-3.0.4.1.7z`。

**原因**：工具链默认从 GitHub Releases 拉；镜像站的目录结构、以及
`ELECTRON_BUILDER_BINARIES_DOWNLOAD_OVERRIDE_URL` 覆盖后的 URL 又会导致缓存键不匹配。

**处理**：**放弃 NSIS**，改自解压方案（自己编译 C# 宿主）。

## 三、安装器（自解压）

### 12. .NET 的 ZipArchive 读不了内嵌 zip

**现象**：`中央目录结尾中应包含的条目数与中央目录中的条目数不对应`，内嵌流读到 0 条目。

**原因**：EOCD 里的中央目录偏移按"绝对流位置"解析，而 zip 是从 exe 尾部偏移开始的。

**处理**：先把载荷落成独立临时文件，再用 `ZipFile.OpenRead` 打开。

### 13. .NET 处理不了 260+ 字符路径

**现象**：`完全限定文件名必须少于 260 个字符`，解压到 6174 个文件就断。

**原因**：运行时树里最长相对路径 210 字符，加上临时目录前缀必超限；
且 .NET 的递归遍历会用旧式路径规范化。

**处理**：**解压交给系统 `tar.exe`**（原生支持长路径），
并且在 C# 里**不要**递归遍历文件系统做统计。

### 14. `install.ps1` 会被当成 ANSI 读取

**现象**：安装脚本"执行成功"但什么都没发生，退出码 0。

**原因**：PowerShell 5.1 对无 BOM 的 `.ps1` 按 ANSI 解析，中文注释与提示变成乱码，
脚本逻辑被破坏且不报错。

**处理**：脚本**必须带 UTF-8 BOM**。

### 15. `Start-Process -ArgumentList` 遇空格路径要加引号

**现象**：`robocopy` 静默复制了 0 个文件；`electron.exe: bad option`。

**原因**：`-ArgumentList @($a, $b)` 中带空格的项会被再切分。

**处理**：每个含空格的参数显式包引号：`'"' + $path + '"'`。

### 16. `cmd /c rmdir` 在含空格路径上失败，且会中断整个安装

**现象**：`The filename, directory name, or volume label syntax is incorrect`，
随后 `$ErrorActionPreference='Stop'` 直接终止安装，快捷方式与注册表都没写。

**处理**：删掉 `cmd /c rmdir`，旧文件交给 `robocopy /MIR` 处理。

## 四、构建流程

### 17. 7z 必须指定工作目录

**现象**：归档只有 22 字节，日志里是 `Scan WARNINGS: 3 win-unpacked : 系统找不到指定的文件`。

**原因**：`spawn` 没传 `cwd`，7z 在错误目录里扫描。

**处理**：`make-payload.mjs` 显式传 `cwd: STAGE`。

### 18. 归档里的中文条目

**现象**：.NET 解压出的中文文件名是乱码。

**原因**：zip 条目的 UTF-8 标志位没置。

**处理**：7z 加 `-mcu=on`（本方案里应用目录全是 ASCII 文件名，属额外保险）。

### 19. stage 是镜像副本，不同步就会打进旧内容

**现象**：改了源码重新打包，安装出来的还是旧行为。

**原因**：`stage/win-unpacked` 是上次的副本。

**处理**：`make-payload.mjs` 每次先 `robocopy /MIR` 同步，并对关键依赖做存在性自检。

### 20. 打包需要停止正在运行的应用

**现象**：`EBUSY: resource busy or locked`。

**原因**：有进程正从该目录运行（例如从 `win-unpacked` 直接启动过）。

**处理**：从安装目录启动应用，不要从构建输出目录启动；
安装脚本自身会先结束旧实例再替换文件。

## 五、其他

- **Electron 只有 default 导出** 同样影响 `preload`：`preload.ts` 会 import 运行时常量，
  直接 tsc 会留下 `require("./ipc.ts")`，所以必须用 esbuild 打成自包含 CJS。
- **图标**：`signAndEditExecutable: false` 会连图标与元数据一起跳过；
  想保留图标只跳过签名，应使用 `signExecutable: false`。
- **环境变量继承**：`ELECTRON_RUN_AS_NODE` 一旦残留在环境里，
  `electron.exe` 会按 Node CLI 解析参数并报 `bad option: --user-data-dir`。
