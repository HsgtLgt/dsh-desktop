# 架构说明

## 运行时布局

安装后 `%LOCALAPPDATA%\Programs\DeepSeek Harness` 的结构：

```
DeepSeek Harness.exe            Electron 壳（GUI）
resources/
└── app/                        应用目录（asar 关闭，真实文件）
    ├── lib/                    壳代码（含 postbuild 修补）
    │   ├── main.js             入口包装（记录 import 失败）
    │   ├── main.impl.js        真正的主进程
    │   ├── preload.cjs         → 渲染进程桥
    │   └── renderer/           启动页 / 插件管理页
    ├── node_modules/           壳的依赖（electron-updater、semver、
    │                           @deepseek-ai/dsh-home-paths）
    ├── dsh/                    dsh 运行时树
    │   ├── desktop-runtime.json   完整性清单（2.3 万文件哈希）
    │   └── node_modules/
    │       ├── @deepseek-ai/dsh            主包
    │       ├── @deepseek-ai/dsh-desktop-host   私有 Host
    │       └── …（扁平化提升的全部依赖）
    └── runtime/                随包分发的可执行运行时
        ├── node/node.exe       内置 Node 24.17.0
        ├── pnpm/               内置 pnpm
        └── versions.json
uninstall.cmd
```

## 进程模型

```
DeepSeek Harness.exe（Electron 主进程）
  ├── GPU / renderer / utility 子进程（Chromium）
  └── runtime/node/node.exe  ← 内置 Node，跑 dsh-desktop-host
        └── 加载 resources/app/dsh 运行时，通过字节管道与壳通信
```

- Host 用**内置 Node**运行（不是 Electron），避免 addon 指纹校验
- 壳与 Host 之间走 fd 3 / fd 4 的帧化字节管道承载 Fetch 流量，Node IPC 只用于生命周期
- 应用界面通过自定义协议 `dsh-app://` 提供，不监听任何端口

## 打包态与开发态的差异

| 项目 | 开发态 | 打包态 |
|---|---|---|
| 判定 | `app.isPackaged === false` | `true` |
| Host 可执行文件 | `DSH_DESKTOP_NODE_BINARY`（系统 Node） | `resources/app/runtime/node/node.exe` |
| 运行时目录 | `DSH_DESKTOP_DSH_DIR` | `app.getAppPath()/dsh` |
| profile | `apps/desktop/.desktop-build/development/project` | `$DSH_HOME/profiles/desktop` |
| 运行时校验 | 传给 Host `--allow-linked-profile` | 严格校验 `desktop-runtime.json` 的文件哈希 |
| 插件管理菜单 | 禁用 | 可用 |

## 安装包结构

```
DSH-Setup.exe =
  [ setup.exe ]           C# 宿主（约 33 KB，含图标与 longPathAware 清单）
  [ payload.zip ]         未打包应用 + install.ps1 + uninstall.cmd（deflate）
  [ uint32 长度 ]         载荷字节数
  [ "DSHSFX1_PAYLOAD" ]   15 字节尾标记
```

setup.exe 的工作流：

1. 读自身末尾 23 字节 → 校验标记、取出载荷长度、算出偏移
2. 把载荷复制成临时文件 `payload.zip`
3. 调用系统 `tar.exe -xf` 解压到临时目录（原生长路径支持）
4. 用 `cmd /c` 调 `install.ps1` 并捕获其输出
5. `install.ps1` 用 `robocopy /E` 复制到安装目录，建快捷方式、写注册表、启动应用

## 为什么不改官方源码

`bootstrap.mjs` 只下载官方源码，不动它；所有修补都在**构建产物**上做（`postbuild.mjs`）。
好处是官方更新时，重新 bootstrap 到新 tag 即可，不用维护源码补丁。
代价是这些修补依赖官方的代码形态（例如 `process.execPath` 这种字面量），
官方若改写相关代码，`postbuild.mjs` 需要同步调整。
